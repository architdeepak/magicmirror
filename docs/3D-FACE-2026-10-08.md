## Available now

Settings → Avatar appearance → **3D face · preview**, or local command “use 3D face.” “Use portrait face” restores the prior appearance. Queen and Snow are supported. Advit has no authored compact face rig and falls back to portrait with an explanation. The preference survives reload. No generative service or additional API is required for this renderer.

The face uses actual triangle geometry and local morph deformations. Eyeballs, irises, pupils and glints rotate independently; hair, skull and Queen crown have solid geometry. The earlier flat hair plate is gone from this path. Mouth cavity and upper teeth support jaw opening. The existing expression mixer, speech/viseme inputs, tracked gaze, manual gaze override, autonomous blinks and deliberate head performance feed this renderer.

The previous lab GLBs had 52 named targets but only jaw and two eyelids changed positions. The runtime rebuilds **37** useful local deformation channels from their neutral geometry. Eight eye-look inputs are represented by independent eye rotation through the gaze input, rather than mesh distortion. Some named channels, including tongue, remain unsupported. This is not a finished ARKit-52 asset or full phoneme-perfect rig. Normals are authored for each deformation so lighting follows the changed surface.

Rendering shares the existing frame scheduler. It allocates no animation timer, reuses settled poses, and follows the display profile's pixel cap. The portrait canvas stops painting when the 3D performer owns the surface. Generated video takes exclusive visual ownership. Depth-room mode still stages the avatar's rendered canvas onto a room plane; it does not embed the full facial mesh in that room's camera.

A graphics failure restores portrait, updates the selector/status and discards the failed renderer. Stale loads cannot change the selected appearance. Persona loads dispose superseded resources. The rig uses bounded geometry, standard materials, a precomputed reflection environment and no per-frame reflection capture, shadows or bloom passes. These choices do not establish wattage or physical PC-stick speed.

## Evidence and visual limits

See [verification](3D-FACE-VERIFICATION.json), [Queen neutral](media/queen-3d-neutral.jpg), [Queen side turn](media/queen-3d-turn.jpg), [Snow](media/snow-3d-neutral.jpg) and [animation preview](media/queen-3d-preview.mp4).

Unit checks cover both meshes, actual nonzero channels, local eyelid/jaw ownership, unchanged neutral geometry, finite normal targets, solid accessories, atomic surface switching, late load cancellation, missing-persona fallback and video exclusivity. Packaged software-GL checks exercise neutral, blink, brow, AA, OH, smile, turns and gaze; they also check quality caps, settled reuse, persona selection, reload persistence, Stop and forced context loss. The general layout and wardrobe journeys were exercised separately. These are explicit inputs, not physical camera/gesture or new-phrase acoustic recognition tests.

Early captures exposed an invalid empty morph-normal array and face occlusion caused by the imported material's disabled depth writes. Both were corrected. An earlier reload assertion referenced the debug object before initialization; its wait now checks the new document generation. Passing the runtime checks is not a visual approval gate.

The short animation advances the production rig through 96 deterministic frames at 24 fps. It is an offline export with explicit expression/gaze/head inputs and no audio. It does not demonstrate live 24 fps or lip synchronization with a spoken recording. The 3D path's physical Windows performance is unverified.

The preview improves independent control and real side rotation, but the hair is still stylized procedural geometry, the crown needs artistic refinement, and the facial topology comes from a reconstructed front surface with an approximate posterior skull. Extreme side views, finely sculpted eyelids, mouth interiors, tongue and accurate skin materials need more work. The portrait remains the default until this visual standard is met. The full suite goal remains incomplete.
